# 🍷 Винна карта (WineCard)

## Опис проєкту

**Винна карта** — це Android-застосунок для перегляду каталогу вин, ознайомлення з їхніми характеристиками та створення власної колекції улюблених вин.

Застосунок розробляється в межах лабораторних робіт протягом семестру.

## Основні екрани

1. **Каталог вин** — перегляд списку вин із зображеннями та фільтрацією за типом.
2. **Деталі вина** — інформація про вибране вино, його регіон, рейтинг і зображення.
3. **Мій погріб** — окрема добірка улюблених вин.
4. **Налаштування** — налаштування застосунку.

## Технології

- Kotlin
- Android Studio
- Jetpack Compose
- Retrofit, kotlinx.serialization, HTTPS JSON
- Coil
- Preferences DataStore
- Git та GitHub

## Джерело даних

Каталог містить 120 записів на основі SampleAPIs: по 30 червоних, білих, рожевих та ігристих вин. Дані завантажуються через Retrofit із віддалених статичних JSON-ресурсів у каталозі [data](https://github.com/kosta223g/WineCard/tree/main/data); резервне джерело — jsDelivr. API-ключ не потрібен.

[Оригінальний набір SampleAPIs](https://github.com/jermbo/SampleAPIs/blob/ebb3f290ad83447e1c503998eaab8bcb4bfafc08/server/api/wines.json). Рейтинги 3,1–4,9 демонстраційні, а кількість оцінок збережена з джерела.

## Локальне збереження

Параметр сортування зберігається у Preferences DataStore. Набір ID улюблених вин зберігається в тому самому DataStore.

## Основні можливості

- Перегляд каталогу вин.
- Фільтрація каталогу за типом вина.
- Перегляд інформації про вино.
- Сортування вин за рейтингом (реалізовано).
- Додавання вин до обраного (реалізовано).
- Перегляд власної колекції (заплановано).

## Лабораторна робота №1

**Тема:** Ідея застосунку на екрані.

**Мета:** визначити концепцію застосунку, його основні екрани, джерело даних і створити початковий інформаційний екран в Android Studio.

## Лабораторна робота №2

**Тема:** Головний екран застосунку.

- Створено модель `Wine` та вкладену модель `WineRating` з назвами полів, сумісними зі структурою API SampleAPIs.
- Додано окремий демонстраційний список із трьох червоних вин.
- Зверстано каталог у `Scaffold` із `TopAppBar`.
- Картки побудовано з використанням `Column`, `Row` та `Box`.
- Додано три локальні векторні зображення пляшок у `res/drawable`.
- Відображаються назва вина, виробник, регіон і рейтинг.

Демонстраційні рейтинги та кількість оцінок не є перевіреними даними API. На лабораторній роботі №7 список буде замінено даними SampleAPIs.

## Лабораторна робота №3

**Тема:** Головна дія користувача.

**Формулювання головної дії:** користувач обирає тип вина у верхньому рядку фільтрів, після чого каталог показує лише вина вибраного типу або повідомлення, якщо таких вин немає.

- Додано поле `category` до моделі `Wine`.
- Для демонстрації фільтрації використано шість вин.
- Додано категорії «Усі», «Червоне», «Біле», «Рожеве» та «Ігристе».
- Реалізовано горизонтальний ряд перемикачів на основі `FilterChip`.
- Стан вибраної категорії зберігається в `WineCatalogScreen` через `remember` і `mutableStateOf`.
- Компонент `WineCategorySelector` отримує список категорій, поточний вибір і callback `onCategorySelected`.
- Каталог динамічно фільтрується за полем `category`.
- Для категорії без результатів («Ігристе») показується окремий порожній стан із повідомленням.

Поле `category` є локальною класифікацією для інтерфейсу, а не заявленим полем відповіді API. Демонстраційні рейтинги та кількість оцінок не є перевіреними даними API.

## Лабораторна робота №4

**Тема:** Застосунок не втрачає вибір користувача.

- Створено `WineCatalogViewModel` і перенесено в нього стан каталогу та демонстраційні дані.
- Описано окремий незмінний стан `WineCatalogUiState` з полями `val`.
- Властивість `uiState` має `private set`, а зміна категорії відбувається через подію `onCategorySelected` та метод `copy()`.
- Екран отримує ViewModel штатною функцією `viewModel()` з бібліотеки Lifecycle ViewModel Compose.
- Прибрано локальний `remember` для вибраної категорії. Стан прокручування залишається локальним.
- ViewModel зберігає вибір під час перестворення Activity, зокрема під час повороту екрана.

**Перевірка:** вибрати «Біле» (2 вина), повернути емулятор, переконатися, що вибрана категорія та список не змінилися. Повторити для «Ігристе» (0 вин). Додатково використано SavedStateHandle для відновлення вибору, якщо ViewModel створюється заново із збереженого стану Activity. Це не є постійним збереженням після примусового завершення застосунку.

## Лабораторна робота №5

**Тема:** Екран деталей об'єкта.

- Додано `NavHost` зі стартовим маршрутом `catalog` та маршрутом `details/{id}` (цілочисельний ID).
- Кожне з шести вин має унікальний ID, сорт винограду, типовий смаковий профіль та рекомендації щодо поєднання зі стравами.
- Натискання на картку викликає `onItemClick(id)`; навігація зосереджена у `WineCardApp`.
- ID читається з аргументів маршруту; об'єкт шукається через `findWineById` у повному каталозі.
- Екран деталей прокручується, має стрілку назад та отримує лише об'єкт і `onBackClick`, без NavController.
- Якщо ID відсутній у каталозі, показано повідомлення і кнопку повернення.
- ViewModel має область життя Activity; попередній фільтр зберігається під час повернення з деталей та повороту екрана.

Характеристики, рейтинги та ілюстрації демонстраційні; дані виробників не перевірялися. Перевірка: вибрати «Біле», відкрити Chardonnay, прокрутити деталі, повернутися та перевірити, що фільтр залишився. Повторити для інших вин і після повороту екрана.

## Лабораторна робота №6

**Тема:** Налаштування, які видимо змінюють застосунок.

- Додано маршрут `settings` та кнопку налаштувань у TopAppBar каталогу.
- Параметр «Сортувати за рейтингом» зберігається у Preferences DataStore.
- Делегат `preferencesDataStore` оголошено один раз у `WineSettingsRepository.kt`.
- Читання через `Flow<Boolean>`, запис через suspend-функцію `setSortByRating`.
- Обидва екрани отримують одне значення з Flow; перемикач не має локальної копії в remember.
- За замовчуванням сортування вимкнено. Якщо ввімкнути, відфільтровані вина впорядковуються за спаданням числового рейтингу.
- Налаштування зберігається після закриття та повторного запуску застосунку.

Перевірка: обрати «Усі», відкрити налаштування, увімкнути сортування, повернутися — першим має бути Sauvignon Blanc (4.7). Перезапустити застосунок і перевірити перемикач та порядок. Вимкнути сортування — першим знову Cabernet Sauvignon (4.6).

## Лабораторна робота №7

**Тема:** Справжні дані замість заглушок.

- Retrofit 2.11.0, kotlinx.serialization, дозвіл INTERNET, один екземпляр Retrofit.
- Віддалені дані на основі SampleAPIs; статичні JSON-ресурси розміщені на GitHub, резервний CDN — jsDelivr. Це не динамічний REST-сервер.
- DTO відокремлено від моделі Wine; відсутні поля обробляються безпечно, записи без коректного ID пропускаються.
- ViewModel завантажує дані при створенні та зміні категорії, скасовує попередній запит і відображає стан завантаження.
- Екран деталей використовує отримані дані, збережено фільтрацію, навігацію та DataStore.

## Лабораторна робота №8

**Тема:** Застосунок не ламається без мережі.

- Стан містить типізовану помилку WineLoadError. Окремо відображаються завантаження, помилка, порожній результат і список.
- Перевірка доступної мережі через ConnectivityManager; HTTP/мережеві збої сервера та помилки десеріалізації розрізняються. Відсутня категорія у JSON не вважається порожньою відповіддю; порожній масив — коректний порожній результат.
- Кнопка «Спробувати ще» повторює запит; з порожнього стану можна оновити каталог або змінити категорію.
- Runtime-дозвіл POST_NOTIFICATIONS (Android 13+): у налаштуваннях користувач натискає «Перевірити каталог зі сповіщенням», після дозволу виконується окремий запит і надсилається сповіщення з кількістю завантажених вин. Відмова не впливає на каталог, деталі або сортування.
- Перевірка: вимкнути Wi-Fi та мобільні дані, відкрити застосунок, перевірити помилку; увімкнути мережу та натиснути «Спробувати ще». У налаштуваннях перевірити відмову й надання дозволу на сповіщення.

## Лабораторна робота №9

**Тема:** Каталог застосунку.

- LazyColumn використовує весь отриманий список без обрізання і створює елементи за потреби.
- Стабільний ключ картки — Wine.id, сформований з категорії та ID джерела. Повторні ключі усуваються у uniqueCatalogWines. Заголовок, стани та підвал мають окремі текстові ключі.
- Картку WineCard винесено в окремий файл; вона отримує Wine та onClick.
- Відступи задано через contentPadding і Arrangement.spacedBy на рівні LazyColumn.
- LazyListState піднято у WineCardApp за межі NavHost, тому індекс і зміщення зберігаються при переході до деталей і назад. ViewModel залишається прив'язаною до Activity; повернення з деталей не викликає refresh().
- Сортування та фільтрація списку не змінюють ID; результат сортування запам'ятовується між рекомпозиціями.
- Перевірено актуальну добірку: 30 вин кожної категорії, разом 120 унікальних ключів. Додано тести стабільності та усунення повторів.

**Ручна перевірка:** відкрити «Усі», прокрутити каталог далеко вниз, запам'ятати назву вина, відкрити деталі й повернутися стрілкою назад. Позиція має залишитися тією самою, без індикатора завантаження. Для додаткової перевірки вимкнути мережу після відкриття деталей і повернутися — вже завантажений каталог має залишитися доступним. Пагінація не потрібна.

## Лабораторна робота №10

**Тема:** Обкладинки та швидке оновлення каталогу.

- Coil 2.7.0: AsyncImage на картках та в деталях; однаковий placeholder/error/fallback із векторною пляшкою, ContentScale.Fit, кешування Coil.
- normalizeWineImageUrl у DTO-мапінгу нормалізує HTTPS, відносні адреси Vivino та відкидає некоректні адреси. Cleartext-захист Android не вимкнено.
- Каталог використовує чотири віддалені JSON-ресурси data/reds.json, whites.json, rose.json, sparkling.json. Категорія «Усі» завантажує їх через coroutineScope, async/awaitAll; спільний Semaphore(2) обмежує одночасні запити до джерела. Окрема категорія — один запит, резервний CDN збережено. Це власний консервативний ліміт, не заявлена квота GitHub. Об'єднаний wines.json доступний для сумісності.
- Material3 PullToRefreshBox, окремий isRefreshing, збереження старого списку при оновленні та зрозуміла помилка з повтором, якщо оновлення не вдалося.
- Перевірка: фото в каталозі й деталях, свайп вниз на початку списку, відсутність мережі під час оновлення, повтор після відновлення мережі. Додано тести нормалізації URL.

- Усі чотири віддалені файли категорій та сумісний wines.json містять одну добірку: 120 позицій, по 30 на категорію. Записи відібрано з оригінального набору SampleAPIs за наявністю оригінального PNG product-bottle URL Vivino, без підміни суфіксів, службових SVG та загальних JPG-фотографій. Перевага надана різним URL пляшок.
- Ігриста категорія містить інші види ігристих вин без Champagne (за назвою та регіоном); рожеві записи відібрано за явним позначенням rosé/rosado/rosato. Демонстраційні оцінки збережено в діапазоні 3,1–4,9.
- Формат URL перевірено, доступність та фактичний вміст усіх зовнішніх зображень потребують перевірки на пристрої.

## Лабораторна робота №11

**Тема:** Пошук по каталогу.

- Поточне джерело — статичні JSON-ресурси, окремого пошукового endpoint немає. Пошук локальний по завантажених винах за назвою, виробником і регіоном, без урахування регістру та діакритичних знаків.
- searchQuery, appliedQuery та isSearching належать WineCatalogUiState. Текст зберігається через SavedStateHandle.
- ViewModel скасовує попередній searchJob і чекає 350 мс перед застосуванням непорожнього запиту. Очищення застосовується відразу; жоден пошуковий текст не надсилається на сервер.
- Автодоповнення від першої літери: до п'яти локальних підказок із фото, назвою та виробником під активним полем пошуку. Збіги з початком назви мають пріоритет; натискання відкриває деталі вина. Підказки не здійснюють мережевих запитів, основний список зберігає debounce 350 мс.
- Категорії залишаються видимими і обмежують результати; сортування, картки, стабільні ключі та перехід у деталі збережені.
- Є окремий стан відсутності збігів із текстом запиту та кнопкою «Очистити пошук». Повтор мережевого запиту та жест оновлення використовують єдину функцію requestCatalog і не скидають пошук.
- Додано тести локальної фільтрації. Перевірка: набрати Cabernet, змінити категорію, відкрити деталі, повернутися, ввести неіснуючу назву, очистити пошук; перевірити повтор запиту після відновлення мережі.

## Лабораторна робота №12

**Тема:** Особиста добірка користувача.

- Набір ID зберігається як stringSetPreferencesKey у наявному Preferences DataStore; toggleFavorite виконує атомарну зміну через edit. Об'єкти Wine не зберігаються.
- Сердечка на картках і в деталях використовують спільний Flow збережених ID.
- Екран «Мій погріб» доступний із TopAppBar і нижньої навігації (каталог, погріб, налаштування).
- WineCellarViewModel завантажує актуальні віддалені категорії за збереженими складеними ID незалежно від фільтра та пам'яті каталогу; збережено ліміт паралельних запитів. Видалені з джерела ID не підміняються іншими записами.
- Окремий порожній стан, обробка мережевої помилки, повтор запиту, перехід у деталі.
- Додано тести вибірки за ID. Ручна перевірка: додати вина з різних категорій, відкрити погріб, перезапустити застосунок, зняти позначку з картки та деталей.

## Лабораторна робота №13

**Тема:** Власний вигляд застосунку.

- Макети каталогу та деталей: [світлий](design/catalog-details-light.svg) і [темний](design/catalog-details-dark.svg). SVG є самостійними векторними макетами, які можна імпортувати у Figma.

- Векторна іконка WineCard і системний splash через AndroidX Core SplashScreen.
- Ручна перевірка: перемкнути тему в налаштуваннях WineCard, відкрити всі екрани, порожній погріб, пошук без збігів, помилку мережі; перевірити холодний запуск. Реальний запуск необхідно перевірити в Android Studio.

## Як зібрати

Потрібні Android Studio, SDK 37 і JDK, сумісний із Gradle wrapper проєкту.
Для debug достатньо стандартного local.properties з sdk.dir.

1. Створіть приватний ключ поза репозиторієм через Android Studio (Build → Generate Signed Bundle / APK → Create new), validity 30 years, alias winecard.
2. У кореневому local.properties додайте (приклад для Windows, використовуйте прямі слеші):

```properties
sdk.dir=C:/Users/YOUR_USER/AppData/Local/Android/Sdk
release.storeFile=C:/Users/YOUR_USER/PrivateKeys/winecard.jks
release.storePassword=YOUR_PRIVATE_PASSWORD
release.keyAlias=winecard
release.keyPassword=YOUR_PRIVATE_KEY_PASSWORD
```

Не публікуйте справжні значення. local.properties та файли ключів ігноруються Git. Не зберігайте ключ у папці проєкту.

3. У терміналі Windows:

```powershell
.\gradlew.bat testDebugUnitTest lintRelease assembleRelease bundleRelease
```

Результати: app/build/outputs/apk/release/ (APK), app/build/outputs/bundle/release/ (AAB), app/build/outputs/mapping/release/mapping.txt (R8). Збережіть усі три файли поза Git для цієї версії.
4. Встановіть APK на телефон. Якщо вже встановлено debug із іншим підписом, видаліть його (це видаляє локальні налаштування). Закрийте Android Studio, відкрийте застосунок із лаунчера й пройдіть [чекліст](release-materials/checklist.md).
